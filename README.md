# Практическая работа: фильтрация и сортировка связанных данных в Sequelize

Репозиторий с примерами решения практической работы по фильтрации и многоуровневой сортировке связанных данных в Sequelize (SQLite).

## Структура проекта

- `src/database.js` — конфигурация подключения Sequelize (SQLite in-memory).
- `src/task1/index.js` — **Задание 1**: Пользователи с постами после определённой даты (`INNER JOIN`, вложенный `order`).
- `src/task2/index.js` — **Задание 2**: Все авторы, включая авторов без книг (`required: false`, `LEFT JOIN`).
- `src/task3/index.js` — **Задание 3**: Фильтрация в связях N:M (студенты и курсы, исключение полей `through`).
- `src/task4/index.js` — **Задание 4**: Заказы и товары (двухуровневая сортировка по дате заказа и цене товара).
- `src/task5/index.js` — **Задание 5**: Комбинирование фильтров (родительский `where` + вложенный `include.where`).
- `index.js` — единая точка запуска всех пяти заданий с тестовыми данными и выводом результатов.

## Запуск проекта

Установка зависимостей:
```bash
npm install
```

Запуск всех заданий:
```bash
npm start
```

## Ответы на вопросы для самопроверки

### 1. Почему при фильтрации по полю связанной модели `where` размещается внутри `include`, а не на верхнем уровне?
* **Верхнеуровневый `where`** формирует SQL-условие для полей основной (родительской) модели (`WHERE Users.field = ...`). Если указать там поле связанной таблицы (например, `publishedAt`), СУБД вернёт ошибку `Unknown column / no such column`, так как в таблице пользователей такого столбца нет.
* **Вложенный `where` внутри `include`** указывает Sequelize добавить условие в контекст связанной таблицы (в предикат `ON ... AND ...` при соединении таблиц через `JOIN` или во вложенный подзапрос).

### 2. Что произойдёт с результатом, если убрать `required: true` при наличии `where` внутри `include`?
* В Sequelize, если внутри `include` задан объект `where`, библиотека по умолчанию автоматически выставляет `required: true` (неявный `INNER JOIN`). Поэтому результат запроса не изменится, но явное указание `required: true` считается правилом хорошего тона (best practice), явно выражающим намерение разработчика.
* Если же намеренно указать `required: false` вместе с `where`, поведение изменится на **`LEFT JOIN`**: в результат вернутся **все** родительские записи, а внутри них в массиве связей останутся только те дочерние записи, которые подошли под условие (у родителей без подходящих записей вернётся пустой массив `[]`).

### 3. Как отсортировать пользователей по имени, а их посты — по дате убывания, используя один вызов `findAll`?
Используется многоуровневый массив правил сортировки в параметре `order`:
```javascript
order: [
  ['name', 'ASC'], // 1-й уровень: сортировка родителя (User) по имени
  [{ model: Post, as: 'posts' }, 'publishedAt', 'DESC'] // 2-й уровень: сортировка связанной модели (Post)
]
```
Если в ассоциации был объявлен псевдоним (`as: 'posts'`), его обязательно нужно указывать внутри объекта `{ model: Post, as: 'posts' }`, иначе Sequelize не сопоставит связь и выбросит ошибку.

### 4. В чём разница между `required: true` и `required: false` с точки зрения типов JOIN?
- **`required: true`** транслируется в **`INNER JOIN`**. Возвращает только тех родителей, у которых **есть хотя бы одна** подходящая связанная запись. Родители без связей отсекаются.
- **`required: false`** транслируется в **`LEFT OUTER JOIN`**. Сохраняет **всех** родителей. Если у родителя нет связанных записей, поле будет содержать `[]` (для связей 1:N / N:M) или `null` (для 1:1 / N:1).

### 5. Как скрыть поля соединительной таблицы в запросе N:M?
С помощью опции `through: { attributes: [] }` внутри объекта `include`:
```javascript
include: [{
  model: Course,
  as: 'courses',
  where: { credits: { [Op.gt]: 3 } },
  required: true,
  through: { attributes: [] } // Исключает Enrollment из итогового JSON
}]
```
По умолчанию Sequelize добавляет в каждый объект курса промежуточные поля связующей таблицы (например, `{ Enrollment: { enrolledAt, grade } }`). Передача пустого массива `attributes: []` отключает вывод этих технических метаданных.
